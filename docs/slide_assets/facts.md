# AeroSync - facts for the slides

Every number below is produced by code in this repository. Benchmark numbers come from
`results/summary.json`, generated by:

    aerosync report --scenario all --out results --seeds 42,43,44,45,46

Seeds: [42, 43, 44, 45, 46] (mean over seeds; std in `metrics_summary.csv`).

## Airport and time model

- 12 contact gates G1-G12 in two terminals (T1: G1-G6, T2: G7-G12) + 4 remote stands R1-R4.
- Wide-body capable: G3, G4, G9, G10 and all remote stands (8 stands in total).
- Apron/taxi graph: 42 nodes, 54 edges
  (gates, apron road, service taxiway, remote road, DEPOT, HANGAR).
- Timestep: 5 min. Buffer between flights at a stand: 15 min.
- Look-ahead (gate request / announcement): 60 min before ETA.
- Max hold considered by planners: 120 min.
- Minimum turnaround: 80% of scheduled ground time.
- Remote-stand walking equivalent: 350 m.
- Vehicle speeds (m/min): {'tug': 250.0, 'fuel': 330.0, 'bus': 400.0}; service times (min):
  {'fuel': 20, 'bus': 15, 'tug': 10}.
- Congestion: edge cost x (weather factor) x (1 + 0.3 x aircraft
  movements within +/-10 min at an adjacent stand).

## Gate-agent bid (Contract Net)

    bid = w1*walk_m*(pax/150) + w2*terminal_mismatch + w3*remote + w4*buffer_risk
        + w5*(alpha * neighbour_load) + w6*hold_min + w7*(reassignment + displaced)

- w1 = 0.05, w2 = 40.0, w3 = 60.0, w4 = 25.0, w5 = 100.0,
  w6 = 4.0, w7 = 15.0
- alpha (coordination weight) = 0.3
- neighbour_load = mean share of [start-60, end+60] occupied at 1-hop neighbour stands
  (known only through their STATE_UPDATE messages).
- buffer_risk = max(0, (30 - slack_min) / 30), slack measured beyond the 15-min buffer.
- Award rule: minimum bid, ties broken by stand id. Infeasible stands REFUSE.

## Algorithms

- CSP: variables = flights, values = (stand, hold); backtracking + MRV + degree heuristic +
  forward checking + least-cost value ordering. Node limit 200,000.
- Worked example (diagrams/csp_worked_example.png): 5 flights, 4 stands, solved in
  5 nodes with 0 backtracks and 58 values pruned.
- Min-conflicts repair: max 2000 steps, patience 150,
  random-walk noise 0.2; announced flights are protected (picked last, 3x move penalty);
  falls back to a CSP re-plan of the movable flights if local search stalls.
- A*: edge cost = length / speed x congestion; h(n) = euclid(n, goal) / speed (admissible).
  Example: tug HANGAR -> G7 at 08:40 (rush_hour, seed 42):
  HANGAR -> TW0 -> TW1 -> TW2 -> TW3 -> C -> A7 -> G7, 5.89 min, 17 nodes expanded.

## Metric definitions

- Walk: passenger-weighted mean of walk(stand, preferred terminal exit).
- Departure delay: mean of (actual off-block - scheduled departure) in minutes.
- Gate utilisation: occupied minutes on the 12 contact gates / (12 x window).
- Schedule conflicts: flights whose planned stand was not free when they were ready to
  block on.
- Reassignments: stand changes after the gate was announced (T-60); an ETA slip beyond the
  look-ahead withdraws the announcement (same rule for every controller).
- Decision compute time: total wall-clock ms spent inside the controller per run
  (machine-dependent, not reproducible to the millisecond).

## Headline findings (mean over seeds [42, 43, 44, 45, 46])

- Passenger walking is lowest with aerosync in every scenario:
  - normal_day: aerosync 319 m vs greedy 430 m (-26%) and fcfs 635 m
  - rush_hour: aerosync 352 m vs greedy 513 m (-31%) and fcfs 663 m
  - storm_disruption: aerosync 479 m vs greedy 593 m (-19%) and fcfs 671 m
  - gate_failure: aerosync 395 m vs greedy 503 m (-21%) and fcfs 582 m
- Departure delay: aerosync is on par in calm scenarios and clearly better under disruption:
  - normal_day: aerosync 6.7 min vs greedy 6.0 / fcfs 6.7 min
  - rush_hour: aerosync 9.1 min vs greedy 8.4 / fcfs 8.6 min
  - storm_disruption: aerosync 39.4 min vs greedy 51.9 / fcfs 52.2 min
  - gate_failure: aerosync 15.1 min vs greedy 22.6 / fcfs 21.5 min
- Conflicts at arrival (planned stand not free) nearly disappear with repair:
  - normal_day: aerosync 0.6 vs greedy 7.2 / fcfs 10.2
  - rush_hour: aerosync 0.0 vs greedy 5.2 / fcfs 5.6
  - storm_disruption: aerosync 0.8 vs greedy 23.2 / fcfs 23.8
  - gate_failure: aerosync 0.2 vs greedy 14.8 / fcfs 14.8
- Trade-offs (honest): aerosync changes more announced gates and needs more compute:
  - normal_day: reassignments aerosync 5.8 vs greedy 0.0; compute 1,522 ms vs 133 ms
  - rush_hour: reassignments aerosync 3.2 vs greedy 0.0; compute 615 ms vs 69 ms
  - storm_disruption: reassignments aerosync 7.8 vs greedy 3.0; compute 5,447 ms vs 283 ms
  - gate_failure: reassignments aerosync 3.4 vs greedy 1.0; compute 2,516 ms vs 129 ms
